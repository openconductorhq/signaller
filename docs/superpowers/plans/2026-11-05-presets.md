# Presets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named presets of the whole Signaller setup: save, switch (console only), export to a file, import with a preview; keys stay on the machine, per downstream id and host.

**Architecture:** `console.json` stays the active preset's config, edited exactly as today. A new `presets.json` beside it holds every preset's name and tagline, and the config of each inactive one; switching swaps configs through `App._put` under `App._rlock`, so `rev`/409 covers it. Keys move to `{id: {host: key}}`. Session levers persist in `session_levers.json`.

**Tech Stack:** Python 3 stdlib (router), vanilla JS/CSS under strict CSP (console), TypeScript hooks module (plugin).

**Spec:** `docs/superpowers/specs/2026-11-05-presets-design.md`

## Global Constraints

- Router: Python 3 standard library only; runs as `python3 -E -s`.
- Console: vanilla JS/CSS, CSP `default-src 'self'`: no inline styles or scripts, dynamic colours via `style.setProperty("--c", …)`, no external URLs, reuse helpers `el`, `api`, `NAME`, `label`, `usd`, `tok`.
- Never fail closed: an unreadable `presets.json` or `session_levers.json` falls back (fresh "my setup" / no levers) with a banner, never a dead router.
- Keys never appear in an export, an API answer, a log line, a test fixture or a commit.
- Every new piece of logic gets one test (`tests/test_*.py`, or the plugin's `tests/gate.test.ts`).
- Never test on the live router (port 8787). UI checks run against a scratch router: `SIGNALLER_CONFIG_DIR=<scratch> SIGNALLER_LISTEN=127.0.0.1:8788 python3 signaller.py`.
- Every PUT/POST/DELETE under `/ui/api/` needs a loopback `Origin` (existing CSRF check covers new routes automatically).
- Suite commands: `pytest -q tests`, `claude plugin test plugin/signaller`, `node --check ui/app.js`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A preset file edited by hand or from a newer Signaller (bad JSON, unknown `signaller_preset` version, a rule naming a missing track): preview refuses with a plain reason, nothing is added. → Task 4 test `test_preview_refuses_bad_files`.
2. Switching while the page holds an old config: the page's next config PUT gets 409, not a silent overwrite of the switched-in preset. → Task 4 test `test_switch_bumps_rev`.
3. A downstream id that exists in your setup at host A and in an imported preset at host B: your key is never sent to B, and entering B's key leaves A's intact. → Task 1 test `test_key_follows_host`, Task 3 test `test_switch_keeps_keys_per_host`.
4. Deleting a downstream from one preset while another preset uses the same id and host: the key survives for the other preset. → Task 3 test `test_delete_downstream_keeps_shared_key`.
5. A session lever saved before a restart that names a downstream the now-active preset lacks: requests from that session follow the preset's lever instead of 502ing. → Task 2 test `test_dangling_session_lever_is_ignored`.

### Task 3: The presets store and App operations

**Files:**

**Interfaces:**
- Consumes: Task 1 `Keys.delete(id, url)`.
- Produces (`presets.py`, pure file I/O + validation):
  - `PRESET_FORMAT = 1`; `NAME_MAX = 60`; `TAGLINE_MAX = 200`
  - `load(config_dir) -> tuple[dict, str | None]` → `({"active": str, "presets": [{"name", "tagline", "config": dict | None}]}, banner)`. Missing file → one preset `{"name": "my setup", "tagline": "", "config": None}`, active, written. Unreadable/invalid → moved to `presets.json.bad`, same fresh store, banner `"Your presets couldn't be read; they were moved to presets.json.bad and your current setup is kept as \"my setup\"."`
  - `save(config_dir, store: dict) -> None` (atomic `write_json`, indent 2)
  - `portable(config_json: dict) -> dict`: a copy without `seeded`, without `migrated_off`, and without settings lines whose condition uses the `session` field (`"session" in fields_of(parse_cond(when))`).
  - `check_name(name) -> str` (stripped; 1–60 chars; `ValueError` otherwise) and `check_tagline(t) -> str` (≤ 200).
  - The active preset's entry always has `config: None`; `console.json` is its config.
- Produces (`App`, all under `self._rlock`, persisting with `presets.save`):
  - `App.presets: dict`; `App.preset_names() -> list[str]`
  - `App.save_preset(name: str, tagline: str) -> None`: adds an inactive preset holding `portable(config_to_json(self.routing))` minus nothing else (session lines are dropped here too, by `portable`). `ValueError("a preset named X exists")` on a duplicate.
  - `App.add_preset(name: str, tagline: str, config: dict) -> None`: validates with `config_from_json(portable(config))` (ValueError propagates), stores `config_to_json` of it, inactive.
  - `App.activate_preset(name: str) -> None`: stores `config_to_json(self.routing)` (as is, session lines kept) into the active entry, loads the target's config with `config_from_json`, forces `seeded=True` and `migrated_off=()`, `_put`s it (bumps `rev`), sets target active with `config: None`. Unknown name → `KeyError`.
  - `App.delete_preset(name: str) -> None`: `ValueError` for the active one; `KeyError` for unknown.
  - `App.rename_preset(old, name, tagline) -> None`: edits name/tagline of any preset (used by the card's edit and by export defaults is not needed; keep it for the card).
  - `App.preset_config(name) -> dict`: the config JSON of any preset (active → `config_to_json(self.routing)`).
  - `delete_downstream(id)`: deletes the key for `(id, url)` only when no inactive preset has a downstream with the same id and host.
