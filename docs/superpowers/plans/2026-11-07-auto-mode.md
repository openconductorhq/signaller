# Auto Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lever mode `auto` that sends planning-phase turns to Anthropic and everything else to the execution downstream, decided locally in microseconds from the request's own history plus an optional trained linear model.

**Architecture:** A new stdlib module `autophase.py` reads the phase from `messages` (skill starts, file edits, model-scored human texts) and holds the model scorer. `routing.route` gets an `auto` branch fed by an injected decider; `App` caches one decision per turn and records the last one per session for the lever API. An offline tool (`tools/auto_train.py`, scikit-learn, never imported by the router) trains and evaluates the model on local transcripts and exports a JSON weights file to the config dir.

**Tech Stack:** Python 3 stdlib (router), vanilla JS (console), TypeScript hooks (plugin), scikit-learn in a scratch venv (offline tool only).

**Spec:** `docs/superpowers/specs/2026-11-07-auto-mode-design.md`

## Global Constraints

- Router: Python 3 standard library only, runs as `python3 -E -s`; `tools/auto_train.py` may use scikit-learn but nothing in the router imports it.
- Never fail closed: a missing/unreadable weights file, a malformed history or a scorer error falls back (phase-only, then execution) with a console banner where it's a file problem.
- No prompts, labels, datasets or trained weights in the repo, logs, fixtures or commits. Test fixtures use invented text. The dataset lives in `/private/tmp/claude-502/-Users-amir-Development-claude-router/59f141e3-67b0-4404-9c12-5ec34dec730f/scratchpad/mine/`.
- Weights file: `<config dir>/auto_model.json`.
- Lever value `auto`; reasons `auto:planning` / `auto:execution`; explanation outcome text like `planning (phase: superpowers:brainstorming)` or `execution (model 0.93)`.
- Planning → Anthropic; execution → `auto.execution` if it names a downstream, else the first downstream, else `anthropic`.
- One way only: any end event anywhere in the history means execution (a later planning skill doesn't reopen planning). `#planning` / `#execution` lead tags still decide their own turn.
- Tracks change only between turns: one decision per human turn, held for the whole tool loop.
- Thinking-block drop applies only when the effective lever is `auto` and the track is `anthropic`.
- Schedule (settings) lines apply unchanged (they already run in `prepare()`).
- Test only on a scratch router (8788 + scratch `SIGNALLER_CONFIG_DIR`); never the live 8787. Never read `downstreams.keys.json`, `stats.db` or `.env.*`.
- Plugin version bump to `0.10.0`, `plugin.json` kept one line.
- Commits end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A first turn with no history and no model → execution (default), never a crash; pinned in Task 1.
2. Malformed history (string content, non-dict blocks, `Skill` input without `skill`, `Edit` without `file_path`) → no exception, ignored; pinned in Task 1.
3. Two turns in one session with the same text ("go") get separate decisions (cache key includes the human message's index); pinned in Task 3.
4. A session lever `auto` survives a preset switch that drops the execution downstream (falls back to the first downstream / Anthropic, never refused); pinned in Task 2.
5. A corrupt `auto_model.json` → banner, auto runs phase-only; pinned in Task 3.

- [ ] **Step 3: Implement `autophase.py`.**
  - Walk `messages` once in order with `ended = False`, `opened = None`. User messages with human text: a `<command-name>/<skill></command-name>` naming a planning skill opens; if `score` is given and `score(text) >= s.threshold`, open with `"model %.2f"`. Once ended, nothing reopens. Result: ended → `("execution", why_of_end)`; opened → `("planning", why_of_open)`; else `("none", "no planning signal")`.

  - `drop_old_thinking`: for assistant messages before `human_index(messages)`, remove blocks whose `type` is `thinking` or `redacted_thinking`; leave a message unchanged if that would empty it.
